# Emby Multi Window

Chrome Manifest V3 扩展。它把多个 Emby 播放会话放入一个普通的极简 Chrome
弹出窗口，不使用原生 Picture-in-Picture。

## 功能

- 视频详情页原生按钮区提供“加入更多画面”
- Emby 正在播放时，右下角提供“加入多画面”
- 最多四路视频，每路声音、播放/暂停、音量和片段循环独立
- 使用 Emby `ThumbnailSet` 的进度缩略图预览
- 可配置每路片段 HLS 内存缓存容量上限，关闭画面立即释放
- 选择循环片段后完整预取对应 HLS 分片，完成后停止服务器转码并从内存循环
- 缓存范围在片段前后各保留最多 60 秒保护区，覆盖关键帧、音频预热和时间戳误差
- 只有片段和两侧保护区连续、完整进入内存后，才会提示缓存就绪并停止服务器转码
- 片段缓存使用独立 HLS 会话，从保护区起点向后顺序读取，避免播放会话前进时回头请求临时分片导致 404
- 缓存清单使用纯文本解析，不启动或销毁后台 HLS.js 控制器，避免中断 Emby 的临时转码会话
- 缓存期间可见视频保持在线直连；保护区全部进入内存后才切换到 HLS.js 内存播放
- 缓存流禁用长 GOP 视频流复制，由编码器在 HLS 边界生成关键帧，避免清单时长与实际内容错位
- 循环终点使用逐帧回调判断，避免低频进度事件造成片段末尾拖长
- 缓存进度提示跟随其他覆盖控件自动隐藏，鼠标操作时再显示
- 设置页可将控件自动隐藏延迟调整为 0.5–30 秒，默认 2.5 秒并即时应用
- HLS 片段启动先完成目标 seek 和 MSE 缓冲，再调用 `play()`，避免 Chrome 将启动请求永久挂起
- 补齐保护区后不会再次跳回片段起点，缓存完整后直接停止服务器转码
- 区分内存命中、MSE 写入和解码等待，不以自动重播掩盖解码停顿
- 可将 HLS、内存缓存、MSE 和视频事件自动写入本机诊断日志，不干预播放
- 使用有限的 MSE 前后缓冲，避免长片段或多画面因无限历史缓冲耗尽 Chrome 配额
- 循环回跳等待浏览器完成 seek，不反复重启 HLS 加载器
- 使用独立 Web Worker 完成 TS 解复用和 MP4 重封装，避免阻塞播放/UI 主线程
- 新加入的画面默认优先直连原始文件，不会在打开画面时自动启动内存缓存
- 直连播放先完成元数据加载和初始定位，再同时启动音视频轨道
- 设置页可自定义一个或多个 Emby 服务器网址
- 鼠标和键盘停止操作 2.5 秒后自动隐藏所有覆盖控件
- 关闭单路或整个窗口时上报停止并清理转码会话
- 自动记忆普通窗口大小；设置页可调预览宽度
- 可新建多个独立播放窗口；后续视频加入最近聚焦的多画面窗口
- 在 Emby 中按住 Shift 点击“加入更多画面”可直接把视频放入新窗口
- 拖动画面左上角的排序手柄即可调整窗口内顺序
- 原始文件发生媒体错误或只有声音而无视频帧时，仍可自动回退 H.264 HLS 在线播放
- 右上角仅保留带文字的“新建窗口”按钮

## 安装

### 下载版

1. 下载 [`dist/EmbyMultiWindowChrome-0.7.24.zip`](dist/EmbyMultiWindowChrome-0.7.24.zip)。
2. 解压到一个固定目录。
3. 打开 `chrome://extensions/`。
4. 开启“开发者模式”。
5. 点击“加载已解压的扩展程序”，选择解压后的目录。

### 源码版

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择仓库根目录 `EmbyMultiWindowChrome`。

默认启用 `localhost` 和 `127.0.0.1`。局域网 IP、端口或域名可以直接在扩展
设置页的“适配的网址”中添加，不需要修改 `manifest.json`。省略端口表示允许
该主机的任意端口；也支持 `https://*.example.com` 形式的子域名通配。

## 结构

- `emby-entry.js`：运行在 Emby 页面主世界，建立独立播放会话
- `bridge.js`：在页面与扩展后台之间传递一次性播放数据
- `background.js`：创建/聚焦播放器窗口并保存窗口尺寸
- `player.*`：多画面播放器
- `options.*`：设置页
- `hls.js` / `hls.worker.js`：HLS.js 1.7.0-beta.2 播放器和独立转封装 Worker

## 媒体缓存

普通播放不会写入扩展缓存。设置页可以启用或关闭循环片段的 HLS 内存缓存，
并设置 256 MB–16 GB 的单路
上限；默认值为 4 GB，升级时旧版默认的 256 MB 会自动迁移到 4 GB，手动设置
过的其他容量保持不变。常规缓存以分片 URL 和字节范围为键，采用容量受限的
LRU 淘汰。选择
循环片段且片段缓存已启用时，扩展会为缓存创建独立 HLS 会话，并让可见视频
继续在线直连。缓存会话从保护区起点向后顺序预取全部分片；缓存完整后才将
可见视频切换到 HLS.js 内存播放，并调用 Emby 停止该缓存会话的转码接口。
进入片段缓存时会强制由 HLS.js 接管，即使浏览器报告支持原生 HLS，以确保
分片能够经过扩展的内存加载器。缓存键会忽略认证参数差异，并额外缓存片段
前后最多各 60 秒的解码/预读保护区；片段模式下也会限制 HLS.js 向循环终点以外
继续预取。片段开始播放后会在后台严格按顺序预取，遇到 Emby 尚未生成的
分片会短暂重试；缓存期间仍可正常播放、暂停和调整音量。
当前片段所需分片在准备过程中不会被 LRU 淘汰；若片段超过容量上限，会明确
提示并恢复在线播放。关闭单路画面或整个窗口时会清空对应 `Map` 和
`ArrayBuffer` 引用。片段名称、起止时间和缩略图索引也只在画面加入时读取一次。

直连 MP4 由 `<video>` 直接发起 Range 请求，其缓存由 Chrome 和 Emby 的
HTTP 缓存头控制，扩展无法像 HLS/MSE 一样可靠接管或强制释放。

## 本机诊断日志

双击 `start-diagnostics.cmd` 可启动随扩展附带的日志程序。它只监听
`127.0.0.1:47831`，并将播放器上报的结构化事件写入：

`logs/emby-multiwindow-diagnostics.jsonl`

日志包含每路视频的缓存命中/缺失、HLS 分片加载、Worker 转封装后的 MSE
追加、`buffered` 区间、循环 seek、`waiting` / `stalled`、媒体错误和解码帧
统计。它不会暂停、seek、重启 HLS 或恢复播放。单个日志文件达到 25 MB 时
会轮换为 `emby-multiwindow-diagnostics.previous.jsonl`；请求网址中的 Emby
令牌和 API key 会在插件端和日志程序端各清理一次。
